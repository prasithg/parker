# Plan: "Hey Parker" — local wake word for the companion

Date: 2026-09-01

Status: chairman-directed (Pras: "a robot with just power on and looking
lifeless until I say hey parker, at which point eyes and antenna pop up
and listen intently — as much visual as audial"); implements R2 of
[`2026-09-01-always-available-reachy-companion.md`](2026-09-01-always-available-reachy-companion.md).

## Engine decision

**Chosen: local keyword spotting on the already-shipped faster-whisper.**
While dormant, the companion streams mic PCM (16 kHz) to the local engine
over `ws /parker/converse/wake` — localhost only, nothing leaves the
machine. The engine keeps a ~2.4 s rolling window, runs the warmed
transcriber every ~0.7 s of new audio **only when the window has real
energy** (silence never spins the CPU), and matches "hey + parker-like"
with a fuzzy grammar tuned for effortful/variable speech.

Alternatives rejected:

- **Picovoice Porcupine**: best-in-class latency, but a commercial
  license/account key inside a public MIT project — wrong posture.
- **openWakeWord in-browser (onnxruntime-web)**: no pretrained
  "hey parker" model (custom training is its own project), plus multi-MB
  vendored WASM in the patient surface. A future upgrade path once a
  custom model is trained on consented samples.
- **Web Speech API**: Chrome implementations ship audio to Google — that
  violates "no cloud audio while dormant" outright.

Trade-offs accepted for v1: wake latency ~1–2 s (window + hop + ASR),
continuous low CPU while someone is speaking near the mic (energy gate
keeps quiet rooms free). Both journaled/measurable; the brief's
wake-recall/false-wake metrics come from receipts.

## Semantics

```text
power off      -> nothing runs, nothing listens (unchanged)
power on       -> DORMANT: mic held locally, wake ws open, cloud CLOSED,
                  Reachy lifeless (head sunk, ember eyes barely lit)
"hey parker"   -> wake ws fires -> visual POP (head springs up, eyes snap
                  open bright, antennae perk with overshoot) + soft chirp
                  -> realtime line opens (greeting = the audible ack)
active session -> full duplex as shipped (spoken confirmation etc.)
long quiet     -> the bridge's gentle wrap-up -> goodbye -> closing ->
                  browser drains audio, closes the line, returns to
                  DORMANT (wake listening re-arms; power stays on)
power off      -> everything released, persisted off
```

- Mic ownership is explicit: ONE getUserMedia per power-on, an owner
  object routes frames by mode (`wake` → local ws @16 kHz, `live` →
  realtime ws @24 kHz). Wake→active reuses the held stream — no
  re-prompt, fast activation. Output/mic AudioContexts are created on
  the power gesture and live for the powered-on lifetime (a wake event
  is not a user gesture and could not create them).
- The companion-mode ladder skip is REMOVED: with dormancy to return to,
  the wrap-up → goodbye → closing ladder is exactly the brief's
  "one gentle optional wrap-up"; his voice still stands it down.
- Ambient speech while dormant animates nothing: the expression machine
  gains a `dormant` phase (non-active, overlays cleared, energy ignored)
  and a `wake_detected` event that only fires from dormant.
- If the local model is unavailable, power-on falls back to
  straight-active (take-2 behavior) with an honest card — never a
  silently broken switch.
- Wake evidence: each detection logs a receipt (matched text, window
  energy, latency) and the expression receipts carry
  `dormant -> connecting (wake_detected)` for session review.

## Matcher (PD-speech tolerant, false-wake averse)

Normalized transcript must contain a greeting token ("hey/hay/hi/a/eh")
within two tokens before a parker-like token (exact set + edit-distance
≤1 from "parker"). Bare "parker" without a greeting does NOT wake
(mentioning Parker on TV must not). Unit-tested matrix includes
negatives ("hey partner", "parking", "hey park the car") and effortful
positives ("hey... parker", "hey parka").

## Amendments (2026-09-02, foundation closure — see
[2026-09-01-foundation-closure-overnight.md](2026-09-01-foundation-closure-overnight.md))

- **Fail closed without the local model.** The take-2 "straight-active
  fallback" is gone: `unavailable` on the wake lane turns power OFF with an
  honest card. Dormant privacy (no cloud audio until "Hey Parker") is never
  traded for convenience.
- **Power is engine-owned.** The wake lane presents the owner token +
  generation from the power claim; power-off revokes it in every tab.
- **Same-breath requests survive.** The wake frame carries `tail`; the lane
  stays open ≤ 3 s sending `tail` frames while the line connects; the
  page's first live frame is `{type:"hello", tail}`, which reshapes the
  greeting so "Hey Parker, can you help me" is answered, not greeted away.
- **Grammar, calibrated for Dad (chairman decision).** Bare `a` is no
  longer a greeting; `hey par ker` / `hey parkuh` wake; `hey darker` and
  friends remain accepted extra wakes and are pinned as such.
- **Adaptive energy gate (opt-in, off by default).**
  `parker_wake_relative_gate` (0 = off): with a TV on the model runs
  continuously (~2.6 cores); at 1.3 it runs only on a hop that rises 1.3×
  above the room's low-percentile background, and only once the room has
  been steadily loud for ~20 s (312 → 54 inferences per 4 min of TV
  speech, 0.46 cores, zero false wakes). Off by default because a missed
  wake costs Dad more than CPU costs the machine: the first design gated a
  wake that followed his own speech, and even the redesign would arm after
  ~24 s of unbroken talk. Enabling it is a room-calibration decision.
  `parker_asr_cpu_threads` caps the shared model's threads.
- **Measured limit.** Over continuous TV speech at equal loudness the local
  model transcribes the TV and misses the wake (0/8); at +6/+12 dB a full
  sentence wakes, a bare "hey parker" does not. Evidence and the candidate
  next slice (dedicated wake model or TV-feed cancellation) are in the
  foundation-closure plan; `scripts/wake_soak.py` is the acceptance test.
- **Bounded greeting latch (F3).** "Hey" ... a Parkinsonian pause longer
  than the 2.4 s window ... "Parker" used to miss (no window held both
  words; real base model 0/3 voices at a 3.2 s pause). The detector now
  remembers a greeting heard on its own for `GREETING_LATCH_SECONDS` = 6 s
  of *audio* time and matches the name through the unchanged single-window
  grammar with the greeting prepended (measured silence envelope 6–7 s; 7.5
  s and beyond stay quiet). A window with ≥3 non-greeting tokens (a
  sentence, his or the TV's) clears it; a word or two on a cut syllable
  ("Okay.") does not; a bare "a" never arms it. Ambient-TV soak with the
  latch: 0 false wakes. The wake frame and receipt gain an optional
  `latch_s`.
- **Growing tail window, final flush (F2, lane half).** The tail lane used
  to transcribe a 2.4 s *rolling* window per hop (the first post-wake
  words had slid out by the 5th hop) and sub-hop audio — the ~0.5 s he
  spoke during the wake inference, before the line opened — never ran at
  all. On the hit the route calls `begin_tail(TAIL_WINDOW_SECONDS)` (= 3 s
  tail + one 0.7 s hop): the window grows from the cleared wake point and
  holds everything he says, so every interim `tail` frame is a superset
  transcript (shape unchanged). A new page frame `tail_end` (sent when the
  line opens) makes the lane transcribe whatever it still holds once
  (≥ 0.25 s of new audio, energy-gated), answer `{type:"tail", text, final:
  true}` — empty is still an answer — and close. The loop is sequential, so
  every audio frame sent before `tail_end` is inside that final window.
- **Fail closed on the realistic model failures (F5).** The store only
  normalised `RuntimeError` (the not-installed case); the realistic
  first-run failures — weights not cached while offline, hub unreachable, a
  half-downloaded snapshot — are huggingface_hub's `LocalEntryNotFoundError`
  (a `FileNotFoundError`), which escaped: the wake socket died with no frame
  (the page took the "network hiccup" retry path with power persisted ON and
  the mic open) and `POST /converse/sessions` was a 500. `_warm_transcriber`
  now catches every load failure into the same honest `unavailable` state
  (not sticky — the next flip retries the load). Independently, a model that
  dies *after* warm-up was silent dead dormancy forever: `WakeDetector`
  counts consecutive inference failures (reset on success) and the lane
  sends `unavailable` and closes at `WAKE_FATAL_FAILURES` = 3 (~2.1 s of
  energetic hops); one bad window still never ends dormancy, a quiet room
  never counts, and the warmed model is never discarded.
